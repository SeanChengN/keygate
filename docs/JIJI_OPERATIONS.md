# 吉吉账号与许可证 AI 运营

适用于 Keygate `v0.1.4-dw.4` 与影造 beta7。管理令牌只交给 Keygate 服务器；客户只输入软件许可证。界面使用“吉吉”，协议中的 `provider_id=jiji` 和服务域名保持不变。

## 1. 获取 Access token、Refresh token 与到期时间

1. 在自己的 Chrome 登录吉吉，确认是准备绑定的账号。按 **F12** 打开开发者工具。
2. 打开 **Application（应用）→ Storage → Local Storage**，选择当前吉吉网站源（通常为 `https://www.jiji.cc`）。
3. 找到下列字段。不要混用不同账号或不同登录会话的值。

| 浏览器字段 | Keygate 表单 | 含义 |
| --- | --- | --- |
| `auth_token` | Access token | 账号管理接口的 Bearer 登录令牌，不是模型 API Key |
| `refresh_token` | Refresh token | 换取新登录令牌的凭据，不是 Cookie |
| `token_expires_at` | Access token 到期时刻 | Unix 毫秒时间戳 |

4. 仅把两个令牌直接粘贴到 **产品 → 吉吉账号** 对应密码框中，不写入文本文件、截图、聊天、工单、终端命令或日志。
5. 到期时间应填写本机时区的日期和时间。可在 DevTools Console 运行以下只显示到期时间的代码；它不显示令牌：

```javascript
new Date(Number(localStorage.getItem('token_expires_at'))).toLocaleString()
```

6. 开启后台同步并保存。界面应清空令牌输入框，只显示是否配置及状态，不返回已保存令牌。留空保存会保留服务器密文。

服务器接口 `expires_at` 使用 **Unix 秒**，浏览器的 `token_expires_at` 使用 **毫秒**；手工调用管理接口时应除以 1000，不能直接提交毫秒值。后台界面自行转换，无需手算。

服务器会串行续期并加密保存新 Access/Refresh token。浏览器和服务器共用一组 Refresh token 时，任何一方的续期都可能轮换该凭据；导入后避免让同一网页会话长期并发续期。重新登录或网页换取新令牌后，必要时成组重新录入服务器。出现认证异常／attention 时先核对账号并重新录入，再重试受阻任务；不反复点击或冷却探测。旧 Refresh token、截图中的令牌和备份中的过期令牌不应重新使用。

## 2. 获取分组 ID

1. 打开吉吉的 API Key 管理页，F12 → **Network（网络）→ Fetch/XHR**，刷新列表。
2. 找到 `GET /api/v1/keys` 的请求，在 **Response/Preview** 查看 `data.items`。按自己的目标密钥名称匹配记录，查看 `group_id`，并核对 `group.id`、`group.name`。
3. 如果目标分组尚无密钥，在页面打开创建／编辑 Key 的分组选项，查看读取可用分组的 `GET /api/v1/groups/available` 响应，按 `data[].name` 确认对应 `id`。只查看，不必创建 Key。
4. 分组 ID 是分组对象的 `id`，不是 Key 的 `id`、用户 ID 或列表序号。把确认的值填入 Keygate 的 **吉吉分组 ID**。

分组会下线或变化，权限也因账号而异。53、52 等仅为示例，不是生产默认值；若可用列表没有目标分组，不应猜测或直接填入。运营需另外确认目标分组的模型、价格、倍率及可用性。

## 3. 方案统一调整

在 **方案 → 方案 AI 配置** 修改分组、月额度或三个周期限额，保存并确认影响数量。全部已绑定许可证会被覆盖，包括此前单独调整的配置；未绑定旧证不会自动获得 Key。

修改分组优先就地更新同一 Key，保留 Key 字符串、ID、用量、有效期和月锚点。保存额度不会补满或清零用量；下调至已用额度以下会使 Key 耗尽。被暂停、撤销或到期的许可证保持禁用。分组修改被吉吉拒绝或读回不符时停止处理并显示错误，不自动更换 Key。

“新签发时自动创建专属 Key”只控制以后签发；关闭它不禁用已有 Key。手动补配可以在此开关关闭时使用，但账号同步须启用、方案额度及公共 AI 配置须有效。

## 4. 旧许可证补配与 beta7

- **单张：**许可证详情 → AI 服务 → 创建专属 API Key → 确认。
- **批量：**方案 AI 配置 → 预览旧许可证批量补配，检查可处理数量、跳过原因、单张初始额度后确认。每批最多 500 张，重复相同操作标识不会重复创建；最近批次可在界面重新打开查看。
- 只补配尚未绑定、当前可用的 Movaura 订阅许可证；方案必须零宽限期。已绑定记录跳过，暂停／撤销／到期等不可用记录不补配。需要先续费或恢复的记录，处理完成后重新预览。
- 首次发放完整配置额度，之后按许可证原始月锚点重置，当前周期不会重复补满。不迁移旧手填 Key 的消费，也不禁用用户原来的个人 Key。
- 手动补配不重复发送“许可证创建”邮件。状态变为已同步后，客户在 beta7 **刷新授权**，或等待启动／定时刷新，即可自动取得专属 Key；不必输入 Key 或重新安装。
- 预览后方案版本变化会返回 `AI_CONFIG_CHANGED`；重新预览再提交，不复用过时的额度确认。

## 5. 同步、重置与删除

“保存并同步”“重置总已用额度”“重置周期用量”“更换 Key”是独立操作。普通配置同步不调用重置；更换 Key 会恢复本周期完整配置额度，需明确确认并让客户刷新授权。状态为结果待确认时，按 [AI 恢复说明](LICENSE_AI.md#失败恢复与回退) 处理，不盲目重复请求。

删除许可证仍要求已撤销、没有支付关联。带 AI 绑定的许可证还必须完成远端禁用、没有候选 Key、没有未完成或不明任务。否则返回 `409 AI_DELETE_UNCONFIRMED`；先检查 AI 服务并完成同步。满足条件后本地任务、绑定和许可证在同一事务删除，保留不含密钥的审计。删除本地记录不删除吉吉 Key，已禁用的远端 Key 留作核查。

## 6. 管理接口与迁移

以下均使用既有 `/api/v1/admin` 前缀和权限；响应禁止缓存，不返回完整 API Key 或管理令牌。

| 接口 | 用途 |
| --- | --- |
| `GET/PUT /plans/{id}/ai` | 配置及版本／汇总；保存后覆盖全部已绑定记录 |
| `POST /licenses/{id}/ai/provision` | 单张旧证补配，需 `Idempotency-Key` |
| `GET /plans/{id}/ai/provision-preview` | 可处理记录、原因及配置版本 |
| `POST /plans/{id}/ai/provision-batches` | `revision`、`license_ids`，需 `Idempotency-Key` |
| `GET /plans/{id}/ai/provision-batches` | 最近批次 |
| `GET /plans/{id}/ai/provision-batches/{batch}` | 持久批次与当前进度 |

增量迁移增加方案版本、绑定来源和批次表，不自动创建客户 Key。回滚前关闭新签发和账号同步，确认在途任务；保留新增表和迁移记录，不运行破坏性 down migration。旧二进制不具备手动补配邮件抑制等新规则，不能带着新任务直接回退运行。
