# 寄售许可证库存与 TXT 交付

## 创建与首次激活

许可证列表 → 寄售库存与 TXT 导出，选择 Movaura 产品、有效月付／年付订阅方案和 1–500 张数量。方案须零宽限期，已有合法的吉吉 AI 配置和公共 AI profile；创建库存不依赖“新签发自动配 Key”开关。无需客户邮箱，不生成虚构客户，不发送创建邮件。

每张库存保存方案周期及计费时区快照，初始状态为“待首次激活”。界面的创建时间不是订阅起算时间；未激活前无订阅到期时间，不创建吉吉 Key、不分配月周期。AI 配置随方案统一调整；调整不创建远端 Key。

第一台设备提交有效签名证明后，在同一事务内开始订阅、绑定设备、设置 AI 月锚点并入队配 Key。重试不延长有效期，也不重复建 Key。非法证明不触发起算。暂停、撤销保持优先；未激活库存恢复后仍待首次激活，不能通过续费、改到期日或换方案绕过起算。

客户端使用 beta8。后台准备时显示“正在准备 AI 服务”，每 3 秒继续，最多等待 90 秒；超时可点刷新授权继续，无需再次填写许可证。认证异常、429 和明确失败立即停止，按吉吉运营指南处理任务再继续。不签发缺少 AI 凭据的可用授权。之前创建的普通许可证与 beta7 的行为不变。

## TXT 导出

可以勾选列表中的未激活且未导出库存，或在库存批次中导出整批剩余库存。确认后生成持久导出清单并下载：UTF-8 无 BOM，每行一个完整**软件许可证**，不含标题、客户邮箱或吉吉 API Key。

导出会记录清单和已导出标记，防止重复上架；生成清单不等于平台已接收或客户已购买。下载失败请从历史清单“重新下载原 TXT”，不要重新创建许可证。重新上架前自行核对平台库存，避免一证多卖。此功能不对接寄售平台 API，也不自动认定已售出。

导出仅管理员可用。普通列表、详情、CSV／JSON 继续只显示掩码。所有选中记录必须符合条件且可解密，否则整体报错，不静默减少行数。历史清单可以在激活后重下；原记录已删除或无法解密时拒绝生成残缺文件。

## 管理接口

使用既有 `/api/v1/admin` 前缀和管理员认证。批次与清单创建须有 `Idempotency-Key`；超时重试同一意图保留该值。

| 接口 | 用途 |
| --- | --- |
| POST /licenses/batches | product_id、plan_id、quantity、notes；只返回批次元数据 |
| GET /licenses/batches | 最近 50 个批次 |
| GET /licenses/batches/{id} | 批次和许可证安全元数据，无完整 Key |
| POST /licenses/key-exports | license_ids，最多 500 个；创建导出清单 |
| GET /licenses/key-exports | 最近 50 个历史清单 |
| GET /licenses/key-exports/{id}/download | 下载原 TXT，禁止缓存，审计不含明文 |

服务器 `/license/activate` 对准备中的库存返回 `status=activation_pending`、`meta.retry_after=3`，不返回 token，不缓存这个临时响应。后续请求必须使用新的设备证明；已有设备、起算时间和配 Key 任务复用。

## 删除、迁移与回退

许可证删除仍要求已撤销、无支付关联、远端禁用已确认且无不明任务。AI 占锁返回 `409 AI_DELETE_BUSY`；提交结果无法确认返回 `409 DELETE_RESULT_UNCONFIRMED`，刷新核对而不是盲目重试。空方案删除会事务清理 AI 配置，保留导出／库存／补配历史；有任何状态的许可证或订阅时返回 409。

增量迁移 `20261113_license_inventory.up.sql` 增加库存批次、状态、周期快照和导出清单，不回填旧证。旧二进制无法识别待激活库存；回退前停止新批次、处理在途首次激活、确认既有远端 Key，必要时恢复配套备份，不运行破坏性 down migration。明文 Key 不进入导出清单、日志或普通响应。

## 方案未出现在可选项时

从 dw.6 起，下拉框显示当前产品的全部方案。不符合条件的方案禁选并说明原因，不再静默隐藏。需要启用的月付／年付订阅且宽限期为 0 天；例如宽限期为 7 天时，前往方案管理人工修改后重新打开库存窗口。程序不会自动更改已有方案。创建前还须保存有效 AI 配置并启用吉吉账号同步。

每月额度可设为 0（不限总额），许可证有效期和周期限额仍然生效。
