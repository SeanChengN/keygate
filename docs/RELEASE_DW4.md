## 真实管理接口验收

本轮只创建专用测试方案、两张测试许可证及对应 Key；正式方案配置和旧许可证未修改。

1. 使用浏览器当前认证信息，以内存方式交给独立 HTTP 客户端，再保存至服务端既有加密账号配置；没有将令牌或完整 Key 写入报告、文件或日志。
2. 自动签发开关关闭时创建未绑定测试许可证。单张手动补配成功；再次提交仍指向原 Key。
3. 批量预览只选中另一张符合资格的未绑定记录；提交后创建成功，批次持久进度为已同步。
4. 暂停第二张许可证后，将测试方案分组 `53 → 35`、总额度 `0.01 → 0.02 USD`。返回影响数量 2；两张许可证及远端均读回目标值，Key 字符串、ID、已用额度、三个周期用量和 UTC 到期时间不变。第一张保持启用，第二张保持禁用。
5. 撤销两张许可证，读回两把远端 Key 均禁用。通过新流程删除第一张；数据库确认许可证、绑定、任务均不存在，删除审计仍保留。另一张保留撤销状态，任务全部完成。
6. 独立登录再查询确认收尾、批次进度及正式方案原配置／版本未变；账号同步启停状态恢复至验收前的关闭状态。

吉吉当前账号可用分组没有 `52`，因此实测使用已确认可用的 `53` 与 `35`，不把数字设置为生产默认。真实测试消费为 0；非零消费保留由合成集成测试验证。没有重跑基础付费模型验收，原有基础能力继续引用 Movaura 项目的 `docs/JIJI_API_ACCEPTANCE.md`。
